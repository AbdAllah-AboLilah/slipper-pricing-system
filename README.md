# نظام تسعير السليبر — Slipper Pricing ERP

نظام PWA محلي Local-First لتسعير فواتير شراء السليبر وFoot Wear، مبني على IndexedDB وبمعمارية Modular.
بدون build step وبدون أي dependencies — الملفات اللي في المستودع هي اللي بتشتغل زي ما هي.

## المزايا
- يعمل على الكمبيوتر والموبايل وiPhone/Android.
- **يعمل Offline بالكامل** بعد أول فتح مع الإنترنت.
- IndexedDB للتخزين المحلي، من غير أي سيرفر.
- حفظ تلقائي للمسودة أثناء الكتابة (المسودات الفاضية متتحفظش).
- أرقام فواتير يومية، وتاريخ الفاتورة قابل للتعديل لتسجيل فواتير قديمة.
- الأقسام بتتاخد حرفيًا من عمود "القسم الفرعي" في ملفك — بدون أي تصنيف تلقائي.
- نسبة ربح مستقلة لكل قسم.
- شرائح أسعار قابلة للتعديل، مع قوالب جاهزة تحمّلها على القسم اللي تختاره.
- بحث داخلي يحاكي منطق VLOOKUP.
- موردون وأصناف ERP بدون بيانات seed مسبقة.
- استيراد Master ERP بمعالج من 5 خطوات: الملف → الورقة → صف العناوين → ربط الحقول → معاينة.
- فصل سعر الشراء عن التكلفة الفعلية، مع خصم المورد وأساس ربح قابل للاختيار.
- واجهة Mobile Cards بدون زحلقة أفقية للبيانات والفاتورة.
- استيراد Excel (`.xlsx` / `.xls`) عبر SheetJS.
- تصدير ERP بترتيب أعمدة تحدده بنفسك (مع أزرار ▲▼ لإعادة الترتيب).
- صورة ومشاركة وطباعة حرارية 80مم.
- رفع أصل الفاتورة (صورة أو PDF) وحفظه محليًا.
- حالة ERP ورقم فاتورة ERP.
- Backup / Restore، مع تحقق كامل من الملف قبل استبدال أي بيانات.

## بنية المشروع
```
index.html                  الـshell + مصدر رقم الإصدار الوحيد + شريط الأخطاء
sw.js                       Service Worker (network-first لملفات التطبيق)
manifest.webmanifest        بيانات الـPWA والأيقونات
assets/                     الأيقونات (SVG + PNG بمقاسات 180/192/512)
src/core/db.js              غلاف IndexedDB
src/core/state.js           حالة التطبيق
src/core/utils.js           أدوات مشتركة (تنسيق، Excel، خطوط، debounce)
src/modules/pricing.js      منطق التسعير والشرائح والمطابقة
src/modules/invoices.js     الفواتير والمسودات
src/modules/catalog.js      الموردون والأصناف
src/modules/settings.js     الإعدادات
src/modules/export.js       تصدير ERP
src/modules/receipt.js      الطباعة الحرارية والصورة
src/modules/backup.js       النسخ الاحتياطي والاستعادة
src/app.js                  كل شاشات الواجهة
src/styles.css              التنسيقات
```

## منطق التسعير
```
سعر الكرتونة ÷ عدد القطع        →  سعر شراء القطعة
− خصم المورد %                  →  التكلفة الفعلية
× (1 + نسبة ربح القسم)          →  السعر قبل الشريحة
البحث في شرائح الأسعار          →  سعر البيع النهائي
مطابقة صنف ERP بالسعر بعد الخصم →  اسم الصنف والباركود والاي دي
```
حدود الشرائح مكتوبة بأرقام صحيحة (`[25,30]` ثم `[31,45]`)، والقيم العشرية اللي بينها
بتروح للشريحة الأعلى تلقائيًا — نفس سلوك معادلة `IF` المتتالية في ملف الإكسل الأصلي.

## النشر على GitHub Pages
1. ارفع محتويات المجلد إلى Repository.
2. فعّل GitHub Pages من Branch الرئيسي والمجلد `/root`.
3. افتح رابط Pages مرة واحدة من الإنترنت حتى يُسجّل Service Worker ويُخزّن ملفات التطبيق.
4. بعد كده النظام بيشتغل بدون إنترنت، والبيانات كلها محلية في IndexedDB.

## تحديث الإصدار
رقم الإصدار له **مصدر واحد** في المشروع كله:
1. غيّر `V` و`date` في أول سكريبت داخل `index.html`.
2. غيّر `version` في `package.json`.
3. حدّث `CHANGELOG.md`.

`src/core/utils.js` بياخد الرقم من `window.APP_BUILD`، و`sw.js` بياخده من رابط تسجيله
(`./sw.js?v=…`) — فمفيش رقم إصدار مكتوب باليد في أي ملف تاني.

## قاعدة البيانات
اسم قاعدة البيانات (`slipperPricingDB_v14`) **ثابت ولا يتغيّر** — تغييره يعني ضياع بيانات المستخدم.
أي تعديل في الهيكل بيتم برفع `DB_VERSION` في `src/core/db.js` فقط، و`onupgradeneeded`
بيضيف الستورز الناقصة من غير ما يمس البيانات الموجودة.

## ملاحظة Excel
استيراد وتصدير `.xlsx` يستخدم SheetJS من CDN عند توفر الاتصال. لو مفيش إنترنت وقت التصدير،
النظام بينزّل الملف بصيغة `.xls` بديلة تفتح بنفس الطريقة. الاعتماد على CDN للاستيراد لا يُعتبر
بديلًا عن تضمين مكتبة Excel داخل المشروع إذا كان المطلوب Offline Excel Import بنسبة 100%.
